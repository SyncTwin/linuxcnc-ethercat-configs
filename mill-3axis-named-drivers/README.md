# Фрезер 3 оси + шпиндель на именованных драйверах lcec

Рабочий конфиг стенда, переведённый с `generic` на драйверы устройств. Снят с
железа 13.08.2026, все пять слейвов доходят до `OP`.

Железо: три сервопривода Inovance IS620N (оси X, Y, Z), Wecon VD3E (шпиндель,
режим CSV), каплер Omron NX-ECC202 с модулем дискретного ввода-вывода.

## Что изменилось против ручного конфига

| | было (`generic`) | стало (драйверы) |
|---|---|---|
| `ethercat-conf.xml` | 236 строк | **83** |
| записей PDO руками | 53 | **10** — и все десять принадлежат каплеру, для него драйвера нет |
| описание привода | ~39 строк карты PDO | одна строка |

```xml
<slave idx="0" type="IS620N" name="x"/>
<slave idx="1" type="IS620N" name="y"/>
<slave idx="2" type="IS620N" name="z"/>
<slave idx="3" type="VD3E" name="s"/>
```

Драйверы для IS620N и VD3E живут в нашей ветке апстрима:
<https://github.com/SyncTwin/linuxcnc-ethercat>. Как поставить — см.

## ⚠ Две грабли при переводе, обе стоили запуска

### 1. Имена пинов меняет драйвер

В `generic` имена пинов назначали мы сами через `halPin=`. Драйвер называет их
сам, с префиксом `srv-`:

| было | стало |
|---|---|
| `lcec.0.0.cia-statusword` | `lcec.0.x.srv-cia-statusword` |
| `lcec.0.0.actual-position` | `lcec.0.x.srv-actual-position` |
| `lcec.0.0.following-error` | `lcec.0.x.srv-actual-following-error` |

Обратите внимание на последнюю строку: изменилось не только начало имени.

Заодно меняется адресация: вместо номера слейва в имени пина стоит `name` из
XML, поэтому `lcec.0.0.` превращается в `lcec.0.x.`. Это удобнее — переставили
привод в цепи, имена пинов не поехали.

### 2. Меняется ТИП пина, и HAL узнаёт об этом только при связывании

Самая дорогая из двух. `following-error` мы объявляли в XML как `s32`. Класс
`cia402` экспортирует его как **`u32`**, и запуск падает:

```
HAL: ERROR: type mismatch 'sampler.0.pin.3' <- 'x-drv-ferr'
./machine.hal:148: link failed
```

Лечится на приёмной стороне — в нашем случае каналы `sampler` под following
error переведены в `u32`:

```hal
loadrt sampler depth=3500 cfg=sssussssussssus
# каналы 3, 8, 13 — u32
```

Мораль общая: при переходе на драйвер проверяйте не только имена пинов, но и
их типы — `halcmd show pin lcec` показывает и то, и другое.

## Distributed clocks: `refClockSyncCycles`

В конфиге стоит `-1`, и это не косметика. Замер на этой же шине:

| | `refClockSyncCycles="1"` | `refClockSyncCycles="-1"` |
|---|---|---|
| часы сошлись | нет | **да** |
| `dc-sync-diff` через 40 с | 1 175 551 нс | **103 нс** |
| `phase-jitter` | 22 634 | **0** |

С положительным значением часы расходятся линейно и не сходятся никогда.

И отдельная ловушка: если описать в конфиге только один слейв из длинной цепи,
мастер скажет `Failed to get reference clock time` — опорные часы живут на
первом DC-способном слейве, и он обязан быть в конфиге.

## Прежде чем запускать у себя

- **Масштаб осей** посчитан под нашу механику: ШВП 10 мм, энкодер 23 бита,
  `SCALE = -838860.8`. У вас другая передача — другое число.
- **Пределы и направления** в `machine.ini` относятся к нашему станку.
- `[DISPLAY] DISPLAY = linuxcncrsh` — стенд работает без монитора; для обычной
  машины поставьте `axis`.
- Каплер описан как `generic`, потому что его карта зависит от набора модулей в
  стеке. Замените секцию на свою.
