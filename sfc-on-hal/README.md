# SFC на HAL: шаги и переходы МЭК 61131-3 без ПЛК

Маленькая последовательность «питатель»: по фронту датчика заготовки толкатель
выдаёт её под открытым отсекателем, выстаивает 2 с, затем отсекатель закрывается
и толкатель уходит в ноль. Четыре шага, переход по датчику, переход по окончанию
хода оси, переход по таймеру.

Всё поднимается штатным `halrun` из пакета `linuxcnc-uspace`: без LinuxCNC motion,
без станка, без нашего кода.

```bash
sudo apt install linuxcnc-uspace
cd sfc-on-hal
halrun -f run_demo.hal
```

## Файлы

| файл | что это |
|---|---|
| `feeder.sfc` | программа текстом SFC (МЭК 61131-3, как в CODESYS ST/SFC) — то, что пишет автор |
| `feeder.clp` | та же программа для ClassicLadder: Grafcet (шаги и переходы) + рунги лестницы |
| `feeder.hal` | поток 1 мс, ClassicLadder, «ось» из штатных компонентов, проводка |
| `run_demo.hal` | сценарий прогона: разрешение → датчик → полный цикл → вторая заготовка |
| `run-log.txt` | настоящий вывод `halrun -f run_demo.hal`, сокращены только служебные строки |

`feeder.clp` напечатан нашим генератором из `feeder.sfc` и выложен как есть (комментарии
рунгов переведены). Сам генератор здесь не публикуется — но файл обычный формат
ClassicLadder, его можно открыть в редакторе `classicladder feeder.clp` и править руками.

## Последовательность

```
          enable AND permit
                 |
        +================+
        || X1 wait_part  ||  R_TRIG(part)
        +================+
                 |
                 +  part_edge.Q          (передний фронт датчика)
                 |
        +----------------+
        |  X2 push       |  gate := TRUE
        |                |  MC_MoveAbsolute(srv0, stroke, v_fwd)
        +----------------+
                 |
                 +  srv0.Done            (фронт Done)
                 |
        +----------------+
        |  X3 dwell      |  (ничего, только время шага)
        +----------------+
                 |
                 +  dwell.T >= T#2s      (таймер %T0)
                 |
        +----------------+
        |  X4 retract    |  gate := FALSE
        |                |  MC_MoveAbsolute(srv0, 0.0, v_back)
        +----------------+
                 |
                 +  srv0.Done
                 |
                 +-----> назад в X1
```

## Шаг SFC → что в HAL / ClassicLadder

| элемент SFC | где живёт | пин HAL |
|---|---|---|
| шаги X1…X4 | Grafcet ClassicLadder (`sequential.csv`, шаги с 1: `%X0` модуль затирает) | активность шага рунгом на `%Q2…%Q5` → `classicladder.0.out-02…05` |
| переход «фронт датчика» | рунг TRIG: шаг X1 И контакт по фронту `%I1` → бит `%B2` | `classicladder.0.in-01` ← датчик |
| переход `srv0.Done` | рунг TRANS: шаг И контакт по фронту `%I2` | `classicladder.0.in-02` ← Done оси |
| переход `dwell.T >= T#2s` | рунг TIMERS: таймер `%T0` (основа 100 мс, уставка 20), в переходе контакт `%T0.D` | — внутри ClassicLadder |
| действие `gate := TRUE/FALSE` | рунг OUTPUTS: SET/RESET катушки (присваивание в ST хранится, а не держится шагом) | `classicladder.0.out-06` |
| `MC_MoveAbsolute` | рунги PARAMS (Position/Velocity в `%QF`), EXECUTE и DELAY | `out-00` Execute, `floatout-00/01` Position/Velocity |
| `MC_Power` | рунг POWER: разрешение → `%Q1` | `classicladder.0.out-01` |
| VAR_INPUT `stroke`, `v_fwd`, `v_back` | `%IF0…2` | `setp classicladder.0.floatin-00…02` — живые ручки |
| разрешение схемы | рунг PERMIT: `enable` И `permit` → `%B7`, первый контакт всех рунгов | `in-00`, `in-04` |
| Hold | размыкающий контакт `%I3` в переходах и Execute, плюс катушка `%Q7` (MC_Halt) | `in-03` |

Три места, где наивный перевод SFC на лестницу ломается, и как это сделано здесь:

1. **Execute должен давать новый фронт на каждом шаге движения.** Ось PLCopen
   стартует по фронту Execute. Если два шага движения идут подряд, уровень не падает,
   и второй ход не начнётся. Поэтому Execute = «шаг активен с прошлого такта»
   (рунг DELAY) — между шагами катушка падает на один такт.
2. **`Done` в переходе — по фронту, а не уровнем.** `Done` прошлого хода держится,
   пока не пришёл новый Execute; уровнем переход проскочил бы сразу.
3. **Датчик — по фронту.** В `run-log.txt` видно: после возврата в X1 датчик всё
   ещё `TRUE`, но новый цикл не стартует, пока заготовку не убрали и не положили
   новую. Уровнем лежащая заготовка выдавалась бы по кругу.

## Ось в этом примере — заглушка

В рабочей ячейке выходы `out-00/01`, `floatout-00/01` и вход `in-02` идут в автомат оси
PLCopen MC перед приводом CiA 402. Этот компонент наш и в пример не входит. Чтобы пример
запускался на чистом `linuxcnc-uspace`, ось собрана из штатных компонентов:

- `conv_bit_s32`: MC_Power → state = 1 (Standstill), без этого рунг DELAY не даст Execute;
- `mux2` + `limit3`: пока Execute стоит, позиция едет к цели с `maxv` = Velocity
  и `maxa` = 50 мм/с²; без Execute держит текущую;
- `near` + `and2`: Done = «доехал» И Execute.

Это ровно настолько ось, чтобы проверить последовательность. Нет ошибок привода,
отставания, Busy/Aborted, MC_Halt (катушка `%Q7` выведена, но заглушкой не читается).

## Честные пределы

- **ClassicLadder держит ограниченное число шагов и переходов** — это `#define` в
  `sequential.h`, константа сборки, а не параметр `loadrt`. Длинную программу
  приходится резать на несколько узлов.
- **Таймер `%T` старого типа, основа 100 мс.** Точность — такт основы, не 1 мс потока.
- **Арифметика ClassicLadder целочисленная** (`int`), float — только как пин на входе
  и выходе. Вещественные вычисления внутри программы делаются компонентами HAL.
- **Удержанных переменных (retain), online change, отладчика шагов в стиле CODESYS нет.**
  Программа меняется перезагрузкой `.clp`.
- **Рунг 6×10 ячеек.** Длинное И или ИЛИ из многих осей приходится раскладывать
  через промежуточные биты `%B` рунгом выше.
- Прогон в `run-log.txt` снят в контейнере без RT-ядра (POSIX non-realtime): он
  доказывает логику последовательности, а не джиттер. Времена в метках — паузы
  сценария, а не замер.
