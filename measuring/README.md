# Как замерить то, что обычно обсуждают на глаз

Три вещи, которые сливаются в жалобу «станок дёргается», а мерить их надо порознь.
Всё ниже делается штатными средствами, наш софт для этого не нужен.

## Задержки реального времени

Мерить **до** того, как искать ошибку в профиле движения или в описании шины.

```bash
cyclictest -m -p 80 -i 1000 -h 400
```

Запускать без графической оболочки. Утилиты `latency-test` и `latency-histogram`
поднимают свой поток реального времени и конфликтуют с уже запущенным LinuxCNC, так
что для машины с работающим станком годится именно `cyclictest`.

На нашем стенде после разгрузки системы пик составил 15 мкс. При таком запасе приводы
держат состояние OP устойчиво.

Что это ловит: если процессор занят чем-то ещё, в логе LinuxCNC появляется

```
Unexpected realtime delay on task 0 with period 1000000
```

а приводы начинают отваливаться из OP по одному. Выглядит как проблема настройки
EtherCAT, лечится разгрузкой машины.

## Отставание оси

Пин `joint.N.f-error` показывает, насколько фактическое положение отстало от
командного. Снимать штатным `halsampler`:

```bash
halcmd loadrt sampler depth=10000 cfg=fff
halcmd net fe0 joint.0.f-error sampler.0.pin.0
halcmd net fe1 joint.1.f-error sampler.0.pin.1
halcmd net fe2 joint.2.f-error sampler.0.pin.2
halcmd addf sampler.0 servo-thread
halcmd start
halsampler -c 0 -n 5000 > f-error.txt
```

Дальше считать по столбцам процентиль, а не среднее: интересен именно хвост.

**Ловушка сравнения осей.** На программе с разной длиной ходов ось X у нас показала
медиану 0,27 мм против нуля у Y и Z, и это читалось как «X настроена хуже». Неправда:
X просто дольше был в движении. Сравнивать оси можно только на одинаковом движении с
одинаковой подачей. Тогда числа сошлись: 1,34 мм у всех трёх на подаче 3000 мм/мин.

**Что значит результат.** Отставание пропорционально скорости, отношение одно и то же
на разных подачах: у нас около 37 с⁻¹. Это штатный след позиционной петли, а не
расстройка привода. На прямой он в геометрию не выходит, потому что все оси отстают
одинаково и меняется только фаза. Срез появляется на углах и на дугах.

## Ошибки на линии

Если синхронизация теряется посреди нормальной работы, а не при остановке мастера,
проверьте счётчики ошибок портов у слейвов: RX Error, Forwarded RX Error, Lost Link.

Растут — проблема на проводе: кабель, экран, разность потенциалов между шкафами.
Стоят на нуле, а сбои есть — проблема выше, в мастере и его расписании, смотрите
первый раздел.

## Чем это не является

Разность часов распределённой синхронизации **не годится** как мера разброса прихода
кадров. Это выход петли подстройки локальных часов слейва: она работает дискретными
шагами по знаку невязки и разброс сглаживает, а не показывает. Мерить джиттер надо на
мастере (`cyclictest`) и по счётчикам ошибок на портах.
