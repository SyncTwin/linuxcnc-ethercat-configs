# Привод как шпиндель: скоростной режим CSV через cia402.comp

На нашем стенде настоящего шпинделя нет - его роль играет сервопривод Wecon VD3E
в скоростном режиме. Для шины это ничего не меняет: тот же CiA 402, тот же
cia402.comp, только вместо цели по положению каждую миллисекунду едет цель по
скорости. Всё ниже проверено на живой шине, где одновременно крутятся CSP на осях
(Inovance IS620N) и CSV на «шпинделе» (Wecon) - два вендора в разных режимах
одного профиля работают вместе.

## Как включается CSV

Отдельного пина `csv-mode` у cia402.comp нет - мы его сначала искали. Скоростной
режим включается выключением позиционного:

```
setp cia402.3.csp-mode 0
```

После этого компонент выставляет opmode 9 (cyclic synchronous velocity) и ведёт
привод по скорости.

## Куда писать команду

В `velocity-cmd` (вход, float). И только туда.

Пины `drv-target-velocity` и `drv-target-position` - это ВЫХОДЫ компонента на
шину. Записать в них из HAL нельзя, и попытка обойти это через `conv_float_s32`
- тупик: она снимает жалобу на тип и упирается в запись чужого выхода. Мы этот
круг прошли. Компонент сам считает `drv-target-velocity = velocity-cmd * velo-scale`.

Пины шпинделя в LinuxCNC 2.9 называются `spindle.0.on` и `spindle.0.speed-out`
(в старых примерах из интернета - `motion.spindle.*`, таких пинов больше нет).
Учтите единицы: `speed-out` отдаёт об/мин, а `speed-in` ждёт об/сек - между
обратной связью и `speed-in` нужен делитель 60.

## Единица скорости на проводе

У VD3E это counts/s - проверено сопоставлением уставки 0x60FF и факта 0x606C на
живом приводе. Энкодер 23 бита, то есть 8 388 608 отсчётов на оборот. Для команды
в об/мин масштаб:

```
velo-scale = 8388608 / 60 = 139810.13   # counts/s на каждый об/мин
```

Если между валом серво и вашим механизмом стоит редуктор - делите дальше. У самого
VD3E собственного редуктора нет: 0x6091 = 1:1, тоже проверяли.

## Как проверить масштаб и как его проверять нельзя

Проверка: `M3 S60`, затем смотреть прирост счётчика вала 0x6064 за известное время.
У нас вышло 59,83 об/мин на заданные 60 - ошибка 0,3 %.

Две ловушки:

- **Не сверяйте по `velocity-fb`.** Обратная связь считается через тот же
  `velo-scale` - она подтвердит любую шкалу самой себе. Только счётчик положения.
- **Не сверяйте на малых оборотах.** На S6 та же цепочка дала расхождение 35 % -
  это пульсации регулятора скорости на ползучем ходу, а не ошибка масштаба. На
  S60 стало 0,3 %.

## Шум в логе, который не надо чинить

```
Failed SDO download 0x6060 (error -22)
```

Эта строка появляется при каждом запуске - и при успешных тоже. Объект 0x6060
(режим работы) замаплен в PDO, и привод отвергает попытку записать его ещё и по
SDO. Это не отказ, ничего делать не нужно. Мы потратили время на «лечение»,
прежде чем заметили, что строку печатают и работающие оси.

## Идентификация

VD3E на шине: vid `0x00000EFF`, pid `0x0D3E0001` (из ESI, подтверждено живой
шиной). Правило одного назначаемого TxPDO - как у IS620N: всё едет в 0x1A00.
