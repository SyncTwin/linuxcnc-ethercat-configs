# Как читать ESI и мануал привода - и что из них правда

ESI (EtherCAT Slave Information) - это XML-паспорт слейва от производителя. Мануал -
книга на несколько сотен страниц. Ни то ни другое не хочется читать целиком, и не
надо: ниже - что именно оттуда брать и в каком порядке, по опыту наладки приводов
четырёх вендоров.

## Сначала - кто вообще на шине: объект 0x1018

Единственный надёжный способ опознать привод - идентификаторы производителя и
изделия из объекта 0x1018 (vendor id / product code). Не имя устройства: например,
IS620N имя прошивки на шине просто не сообщает, поле пустое - на всех наших живых
станках. Скрипт, который опознаёт привод по имени, молча не опознает ничего.

Живьём смотреть так:

```
ethercat slaves            # кто на шине и в каком состоянии
ethercat slaves -v         # + identity: vendor id, product code, ревизия
```

По этим же идентификаторам слейва сопоставляет lcec: привод с чужим vid/pid не
выйдет из PREOP.

## Отдаёт ли привод словарь объектов живьём: SDO-Info

Это первое, что стоит выяснить, потому что от ответа зависит, насколько вам нужен
мануал:

```
ethercat sdos              # если список пришёл - SDO-Info поддерживается
```

По нашим приводам: Mitsubishi MR-J4-TM словарь отдаёт, Inovance IS620N и
Schneider LXM28E - нет. Если не отдаёт, карту объектов придётся брать из ESI или
из мануала - с работающего привода её не вычитать.

Но и когда словарь отдаётся, имена в нём приходят кодами вида «PB07» - без единиц
измерения и расшифровки. То есть мануал нужен в любом случае, просто для разного:
при SDO-Info - только для подписей, без него - и для структуры.

## Профильные и вендорские объекты

Индексы 0x6000-0x6FFF - профиль CiA 402, они одинаковые у всех: 0x6041 statusword,
0x6064 позиция, 0x6060 режим. Эту часть можно один раз выучить и не искать в
мануалах вообще.

Индексы 0x2000-0x5FFF - вендорские, и вот тут мануал незаменим. Пример: у Inovance
параметры из мануала вида Hgg-pp адресуются по правилу

```
Hgg-pp  ↔  0x2gg : (pp + 1)
```

коэффициенты контуров - 0x2008, режекторные фильтры - 0x2009, дискретные входы и
выходы - 0x2003 и 0x2004. Это правило в мануале нигде не сформулировано явно -
оно восстанавливается сопоставлением пары known-параметров, зато потом открывает
весь список H-параметров по SDO.

## Раздел про PDO - читать в мануале, а не догадываться по ESI

ESI показывает, какие PDO у привода есть. Но ограничения на их НАЗНАЧЕНИЕ пишут
в мануале, в главе вида «PDO configuration». Наш пример: IS620N назначает ровно
один передающий PDO - либо 0x1A00, либо один из 0x1B01…0x1B04. Мы добавили второй,
рассуждая «а вдруг привод ограничивает число записей в одном PDO» - и слейв
перестал доходить до OP c ошибкой сервисного обмена. Тесты при этом были зелёные:
они проверяли наличие строк в XML, а не форму допустимого.

Что выписать из этой главы себе: сколько TxPDO/RxPDO назначается одновременно,
какие индексы допустимы, сколько записей влезает в один PDO с переменным
маппингом (у 0x1A00 IS620N - десять).

## DC-синхронизация

Значение assignActivate для конфигурации мастера берётся из ESI (элемент Dc/AssignActivate;
у всех наших приводов - 0x300, синхронизация по sync0). Если привод в OP не
держится - сначала проверьте задержки реального времени на мастере, а уже потом
крутите DC: у нас срывы синхронизации дважды оказывались перегруженным
процессором, а не настройкой шины. Методика - в папке [`../measuring/`](../measuring/).

## Про распространение ESI

Сами ESI-файлы - произведения вендоров, их распространение регулирует ETG. В этом
репозитории их нет и не будет. Публиковать можно производные факты - идентификаторы,
поддержанные режимы, ограничения на PDO - со своей интерпретацией и своими
замерами. Наши собраны в реестре, у каждого факта помечен источник:
<https://synctwin.ru/ethercat/>
