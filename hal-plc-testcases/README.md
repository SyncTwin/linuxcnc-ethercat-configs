# HAL против CODESYS: 18 воспроизводимых тест-кейсов

Публичный набор для проверки утверждения «HAL LinuxCNC закрывает бо́льшую
часть стандартной библиотеки CODESYS / IEC 61131-3» — той части статьи на
Хабр, которую нельзя просто прочитать и поверить на слово. Каждый кейс — это
`.hal`-файл, который поднимается сам по себе в `halrun`, без LinuxCNC и без
реального станка, и лог того самого прогона рядом.

Ничего в этом наборе не тянет из внешнего репозитория и не требует нашего
кода — только штатная поставка LinuxCNC (`linuxcnc-uspace` из Debian).

## Как воспроизвести у себя

Нужна любая Debian/Ubuntu-машина или VM (реальное железо станка не требуется,
`halrun` поднимает HAL без него):

```bash
sudo apt update
sudo apt install linuxcnc-uspace
cd hal-testcases
./run_all.sh
```

Раннер прогоняет каждый `NN_имя.hal` через `halrun -f`, кладёт вывод в
`results/NN_имя.log` и печатает сводку (сколько поднялось / отказало, версия
LinuxCNC, ядро). Логи в этом наборе сняты 21.08.2026 на `linuxcnc-uspace`
2.9.10, ядро `6.1.0-51-rt-amd64` — своя версия может отличаться числами, но
не логикой; если поведение разошлось — это находка, а не шум, и её стоит
разобрать отдельно.

Повторная проверка 02.10.2026: тот же набор прогнан в контейнере Debian 12 с
пакетом `linuxcnc-uspace` 2.9.0~pre1 без RT-ядра (POSIX non-realtime) — 18 из 18
поднялись, значения битов в логах совпали с лежащими здесь. Под `root` `halrun`
откажется стартовать; в контейнере достаточно `RTAPI_UID=1000
RTAPI_FIFO_PATH=/tmp/.rtapi_fifo ./run_all.sh`.

Пример того же HAL как исполнителя последовательности SFC (шаги, переходы, таймер,
ход оси) — в соседней папке [`../sfc-on-hal/`](../sfc-on-hal/).

Скрипт отказывается запускаться, если на машине уже поднят живой LinuxCNC
(`linuxcnc`/`milltask`/`rtapi` в процессах) — `halrun` снимает realtime-домен
за собой и убьёт работающий контур.

## С чем сравниваем

Слева — стандартная библиотека CODESYS / блоки IEC 61131-3 (TON, TOF, CTU,
SR-защёлка, PID и т. д. — то, что есть в любой ПЛК-среде из коробки). Справа —
штатная поставка LinuxCNC HAL: компоненты из `man9`, без сторонних
дополнений и без наших собственных наработок. Сравнение узкое и
проверяемое читателем, а не «в целом одно и то же».

## Статусы прогона — читать буквально

- **прогнано** — кейс поднялся и лог показывает заявленное поведение.
- **прогнано (перепрогон): …** — первая попытка на что-то не отвечала честно
  (не туда смотрели, не хватало паузы на такт потока, спутан фронт/уровень),
  кейс переписан, и лог, который лежит в `results/`, снят уже с исправленной
  версии. Что именно было не так — в примечании.
- **опровергнуто** — компонент существует и прогнан, но НЕ делает то, что
  можно было бы принять за аналог: `10_arith` показывает, что `minmax` следит
  за экстремумами величины ВО ВРЕМЕНИ, а не выбирает большее/меньшее из двух
  значений (это делает связка `comp` + `mux2`, отдельно не оформленная в
  кейс).
- **доказана только часть** — `11_scale_analog` подтверждает линейную формулу
  масштабирования 4–20 мА и ничего не говорит про обрыв датчика: `scale` и
  `offset` в HAL это не различают в принципе.

Три отдельных предупреждения, которые обязаны остаться на виду, а не
потеряться в общем «зелёном» статусе:

1. **`09_limit` / `limit2`, `limit3`** — числа в логе показывают, что при
   `maxv=5` фильтр НЕ прыгает на цель мгновенно: за 0,05 с выход дошёл до
   0,265, за 0,5 с — до 2,52 (цель 100). Это ожидаемое поведение ограничителя
   скорости, но с ходу читается как «завис» — в логе разбор по шагам.
2. **`12_hysteresis` / `comp`** — вход `in0` компаратора инвертирующий: выход
   истинен, когда `in1 > in0`. Если перепутать местами величину и порог,
   логика срабатывает НАОБОРОТ замыслу. Кейс в этом наборе уже учитывает
   инверсию; при переносе схемы к себе — проверить, куда именно подан порог.
3. **`16_watchdog`** — сторож ловит ОТСУТСТВИЕ ОБНОВЛЕНИЙ входа, а не его
   уровень: `input-0` может стоять в `TRUE` неизменно, `ok-out` всё равно
   уйдёт в `FALSE`, если сигнал перестал ДВИГАТЬСЯ дольше таймаута.

Полная таблица покрытия с построчными примечаниями и обзором того, чего в
HAL нет вовсе (retain, online change, ST/IL как язык, сертификация
IEC 61508/ISO 13849, OPC UA) — в статье на Хабр; здесь — только
доказательная часть.

## Список кейсов

| файл | что проверяет |
|---|---|
| `01_ton.hal` | TON — задержка включения (`timedelay`, `on-delay`) |
| `02_tof.hal` | TOF — задержка выключения (`timedelay`, `off-delay`) |
| `03_tp.hal` | TP — импульс заданной длины (`oneshot`) |
| `04_rtrig.hal` | R_TRIG / F_TRIG — фронты (`edge`) |
| `05_sr.hal` | SR / RS — защёлка (`flipflop`) |
| `06_latch_selfhold.hal` | самоудержание пуск/стоп (`or2`+`and2`+`not`) |
| `07_ctu.hal` | CTU/CTD/CTUD — счётчик (`updown`) |
| `08_mux_sel.hal` | SEL/MUX — выбор значения (`mux2`) |
| `09_limit.hal` | LIMIT/RAMP — ограничение величины и скорости (`limit1`,`limit2`,`limit3`) |
| `10_arith.hal` | ADD/MUL/DIV/ABS/MIN/MAX (`sum2`,`mult2`,`div2`,`abs`,`minmax`) |
| `11_scale_analog.hal` | масштабирование аналога 4–20 мА (`scale`,`offset`) |
| `12_hysteresis.hal` | компаратор с зоной нечувствительности (`comp`, `hyst`) |
| `13_debounce.hal` | подавление дребезга входа (`debounce`) |
| `14_lut5.hal` | произвольная функция пяти входов (`lut5`) |
| `15_pid.hal` | PID-регулятор (`pid`) |
| `16_watchdog.hal` | сторож живости задачи (`watchdog`) |
| `17_two_tasks.hal` | несколько потоков с разными периодами |
| `18_sampler.hal` | трассировка переменных в реальном времени (`sampler`) |

## Что НЕ входит в этот набор

- **`classicladder`** (LD/SFC-редактор из штатной поставки LinuxCNC) — в
  тест-кейсы не оформлен, разбор по исходникам — в статье.
- Собственный слой авторов набора поверх HAL (генератор своих `.comp` из
  описания программы) — не публикуется здесь: он не самодостаточен без
  внутреннего кода авторов, а этот набор обязан запускаться только со
  штатным `linuxcnc-uspace`.
- Скрипты замера на реальном приводе через EtherCAT/SDO — работают только с
  подключённым сервоприводом, к сравнению HAL/CODESYS отношения не имеют.

## Лицензия

Сами `.hal`-кейсы и этот README — можно копировать, менять, использовать в
своих целях. LinuxCNC, `halrun` и все компоненты HAL из `man9` — GPL,
проект LinuxCNC. Ставится штатно из пакета `linuxcnc-uspace`.
